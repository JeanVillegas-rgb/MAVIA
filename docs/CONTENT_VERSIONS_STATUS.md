# Content versions: how it works, and what is currently broken

Written 2026-09-10, after the first full publish run on the Grade 1 Science
course. Intended for anyone on the team who has not been following this part of
the pipeline day to day.

## What the feature is

Every learning object a student is taught must exist in three versions:

| Version | Where the text comes from |
|---|---|
| **Original** | The learning object's own content, as extracted from its PDF |
| **Simplified** | An easier presentation of the same concept |
| **Elaborated** | A fuller presentation of the same concept |

Anything left over is stored as an **extra** — kept in the database for the
learning-path component to rule on later, never shown to a student as one of
the three.

## Where the text comes from

Two sources, in order of preference.

**From another PDF, when semantic grouping found the same concept twice.**
If two PDFs both teach "Solid", those are two real passages written by real
teachers. The earliest-uploaded one becomes the original; the other is
classified as simplified or elaborated and becomes a rung of the same concept.
The second object stops being a separate teaching step — it is marked
`represented_by` the first — so the student meets the concept once, not twice.

**From the language model, only for slots real material cannot fill.**
A concept found in just one PDF has nobody to borrow wording from, so Gemma
writes both rungs from the original. A concept found in two PDFs gets one real
rung and one generated one.

This ordering is the point of the feature. Teacher-written text is preferred;
the model fills gaps.

## How simplified vs elaborated is decided

Not by a classifier. A small heuristic compares the two passages on two
signals — Flesch-Kincaid grade level and word count — and only assigns
automatically when the gap is unambiguous:

```
ΔFlesch-Kincaid > 1.5   AND   word ratio ≥ 1.25
AND ΔWords > 10         AND   both signals point the same way
```

If the two signals disagree on direction, or any margin is thin, the pair is
**not** guessed at. It goes to the teacher, who sees both passages side by side
and answers "this is simpler" / "this is fuller" / "keep as extra".

These thresholds are operating values chosen to be conservative. They are not
calibrated against labelled data, and neither is the `0.60` semantic grouping
threshold that feeds them. Both should be revisited once more courses have been
reviewed.

## What the first real publish produced

One topic, 2 PDFs, 69 learning objects. The run took 23 minutes.

| | |
|---|---|
| Versions written | 122 (61 simplified + 61 elaborated) |
| From a second PDF | **5** |
| Generated by Gemma | **117** |
| Objects absorbed into another | 4 (69 → 65 teaching steps) |
| Objects left with no versions | 4 |
| Audio files | 69 |

**The number worth discussing: only 5 of 122 rungs are teacher-written.**
Semantic grouping found 6 pairs among 69 objects, so the mechanism that makes
grouping worth doing is currently carrying about 4% of the content. That is not
a bug — it reflects how much these two particular PDFs overlap — but it is the
first thing an outside reader will ask about.

## Bugs found, in priority order

### 1. Answering the teacher prompt does not clear it, and re-answering duplicates content

**What you see:** you click "this is simpler", the version appears in the
section below — and the prompt is still sitting there. Click a different button
and a *second* version appears, without the first being removed.

**Why:** the list of pairs awaiting a decision is recomputed from every member
of the group each time the screen loads, and nothing excludes a member already
ruled on. Separately, a version row is keyed on `(learning object, slot)`, so
answering a second time writes a **new row in a different slot** rather than
moving the existing one.

**Damage already in the database:** object 436's text is currently serving as
*both* the simplified and the elaborated version of concept 415. A student
would be shown identical text at two different difficulty levels.

**Fix:** exclude settled members from the prompt, and make a teacher decision
move the source between slots instead of adding another. The existing duplicate
needs cleaning up.

### 2. Group members the heuristic could not call end up with no versions at all

**What you see:** a concept is taught with only its original text — no
simplified, no elaborated.

**Why:** when a group member is too ambiguous to assign, it correctly stays a
teaching step of its own. But generation only ever runs for the group's
*representative*, so nobody fills that member's slots.

**Affected now:** objects 427 (`Solid (Part 1 of 3)`) and 470
(`Changes of State`).

**Fix:** generate for every teaching step, not only representatives.

### 3. Very short objects fail generation permanently

**What you see:** `Gemma's simplified variant exceeded the grounding limit.`

**Why:** a simplified version is capped at `max(12, source words + 3)`. For a
16-word object that means 19 words, which leaves almost no room. And unlike
question generation, variant generation has **no retry** — a single overrun is
final.

**Affected now:** objects 452 (24 words) and 483 (16 words).

**Fix:** retry on grounding failure, and reconsider the limit for very short
source text.

## What is not affected

These bugs are all about **version text**. None of them change:

- which learning objects exist, or their order
- `metadata_id`, which stays stable per object
- which objects are teaching steps (`represented_by IS NULL`)
- question pairing, audio, or the outline hierarchy

## Notes for whoever builds on this

The contract the learning-path component should code against is settled even
though the bugs are not:

- **A teaching step is a learning object with `represented_by IS NULL`.**
  There are 65 of them right now, out of 69 objects.
- **A represented object still exists**, keeps its `metadata_id` and its
  question links, and should be skipped when sequencing. Edges that touch one
  should resolve to its representative.
- **Representation is reversible.** Ungrouping clears the flag and deletes the
  generated rungs while keeping the teacher-written ones. Nothing is destroyed,
  because the grouping that produced it is an automatic decision at an
  unvalidated threshold.
